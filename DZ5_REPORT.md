# Отчет по выполнению ДЗ №5

## ✅ Все требования выполнены

### 1. ✅ Взаимодействие системы с ML сервисом посредством передачи сообщений

**Реализация:**
- Используется RabbitMQ для асинхронной обработки ML задач
- Publisher: `app/src/rabbitmq_client.py` - отправляет задачи в очередь
- Consumer: `app/src/ml_worker.py` - получает и обрабатывает задачи

**Файлы:**
- `app/src/rabbitmq_client.py` - класс RabbitMQPublisher
- `app/src/ml_worker.py` - ML воркер с callback функцией

### 2. ✅ Развернуто несколько воркеров

**Реализация:**
- 3 ML воркера запущены в Docker контейнерах
- Контейнеры: `ml-worker-1`, `ml-worker-2`, `ml-worker-3`
- Конфигурация в `docker-compose.yml` (строки 59-129)

**Проверка:**
```bash
docker-compose ps
# Должны быть запущены: ml-worker-1, ml-worker-2, ml-worker-3
```

### 3. ✅ Воркеры подключены к RabbitMQ

**Реализация:**
- Все воркеры подключаются к очереди `ml_tasks`
- Используют одинаковые параметры подключения
- Автоматическое переподключение при ошибках

**Проверка:**
```bash
docker-compose logs ml-worker-1
# Должно быть: "Подключено к RabbitMQ" и "Ожидание задач..."
```

### 4. ✅ RabbitMQ настроен в режиме один издатель - несколько слушателей

**Реализация:**
- **Publisher (один):** 
  - FastAPI (`app/src/routers/predict.py`) - эндпоинт `/predict`
  - Telegram Bot (`app/src/telegram_bot.py`) - отправка задач
- **Consumers (несколько):**
  - 3 воркера слушают одну очередь `ml_tasks`
  - Используется `basic_qos(prefetch_count=1)` для равномерного распределения задач

**Очередь:**
- Имя: `ml_tasks`
- Тип: durable (сохраняется при перезапуске)
- Распределение: round-robin между воркерами

### 5. ✅ Воркеры получают задачу, валидируют данные, выполняют предикт, записывают результат

**Реализация в `app/src/ml_worker.py`:**

1. **Получение задачи из очереди** (строки 191-211):
   - Callback функция `callback()` получает сообщение
   - Извлекает `task_id` из JSON

2. **Валидация данных** (функция `validate_input_data`, строки 45-85):
   - Проверяет наличие всех обязательных полей
   - Валидирует типы и диапазоны значений
   - Возвращает `(is_valid, error_message)`

3. **Выполнение предикта** (строка 150):
   - Вызывает `calculate_prediction(prediction_request)`
   - Получает результат предсказания

4. **Запись результата в БД** (строки 153-174):
   - Обновляет статус задачи: `pending` → `processing` → `completed`
   - Сохраняет результат предсказания в `MLTaskDB`
   - Создает запись в `PredictionDB` для истории

## 🧪 Тестирование

### Тест через REST API

**Шаги:**
1. Регистрация: `POST /auth/register`
2. Авторизация: `POST /auth/login` (получить token)
3. Пополнение баланса: `POST /balance/deposit`
4. Отправка задачи: `POST /predict` (задача отправляется в RabbitMQ)
5. Проверка статуса: `GET /task/{task_id}` (повторять пока статус не станет `completed`)
6. История: `GET /predictions`

**Автоматический тест:**
```bash
# PowerShell
powershell -ExecutionPolicy Bypass -File test_dz5_api.ps1

# Python (если установлен requests)
python test_dz5_api.py
```

### Тест через Telegram Bot

1. Откройте бота `@AI_Court_Order_Bot` в Telegram
2. Отправьте `/start`
3. Зарегистрируйтесь через кнопку "📝 Регистрация"
4. Пополните баланс через "➕ Пополнить"
5. Создайте предсказание через "🔮 Предсказание"
6. Задача отправится в RabbitMQ, воркер обработает её

### Проверка RabbitMQ

1. Откройте RabbitMQ Management UI: http://localhost:15672
   - Логин: `guest`, Пароль: `guest`
2. Перейдите в раздел "Queues"
3. Найдите очередь `ml_tasks`
4. Проверьте:
   - Количество сообщений
   - Consumer connections (должно быть 3)
   - Message rates

### Проверка логов воркеров
