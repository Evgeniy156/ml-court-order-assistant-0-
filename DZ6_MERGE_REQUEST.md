# ДЗ№6: Web-интерфейс для ML Court Order Assistant

## Описание

Реализован полнофункциональный Web-интерфейс на FastAPI + Jinja2 для взаимодействия с ядром системы (Telegram-бот, RabbitMQ, worker, БД, ML-модели). WebUI соответствует требованиям общего задания курса и лекции по уроку 6.

## Что сделано

### 1. Структура webapp

Создана структура `app/src/webapp/`:
- `main.py` - точка входа FastAPI-приложения с Jinja2
- `services.py` - тонкий слой над ядром (БД, RabbitMQ), вся бизнес-логика
- `routes/` - роутеры для веб-интерфейса:
  - `dashboard.py` - главная страница / дашборд
  - `tasks.py` - список задач и детали задачи
  - `models.py` - список моделей и запуск задач
  - `auth.py` - авторизация (логин, регистрация, выход)
- `templates/` - HTML шаблоны:
  - `base.html` - базовый layout с навигацией
  - `index.html` - дашборд
  - `tasks.html` - список задач
  - `task_detail.html` - детали задачи
  - `models.html` - список моделей
  - `login.html` - форма входа
  - `register.html` - форма регистрации

### 2. Функционал

#### Авторизация (/login, /register, /logout)
- Регистрация новых пользователей с хэшированием паролей (bcrypt)
- Вход в систему по email/паролю
- Авторизация через cookie (user_id)
- Автоматический редирект авторизованных пользователей
- Выход из системы с удалением cookie

#### Главная страница (/)
- Агрегированная статистика по задачам:
  - Всего задач
  - Ожидают (pending)
  - Обрабатываются (processing)
  - Завершены (completed)
  - Ошибки (failed)
- Список последних 10 задач с основными полями
- Форма для создания новой ML-задачи (только для авторизованных)
- Приветствие по имени пользователя (если авторизован)

#### Список задач (/tasks)
- Таблица всех задач с полной информацией:
  - ID (ссылка на детали)
  - Статус (с цветовой индикацией)
  - Модель
  - Пользователь (email)
  - Дата создания
  - Дата завершения
- Ссылки на детали каждой задачи

#### Детали задачи (/tasks/{task_id})
- Полная информация о задаче:
  - Статус и временные метки (создана, начата, завершена)
  - Связанная модель
  - Пользователь (email и ID)
  - Списанные кредиты
  - Входные данные (JSON)
  - Результат предсказания (если завершена) - вероятность в процентах
  - Сообщение об ошибке (если failed)
- Навигация: ссылка на список задач

#### Список моделей (/models)
- Таблица всех ML-моделей:
  - ID
  - Название
  - Описание
  - Цена в кредитах
  - Действия (кнопка быстрого запуска)
- Кнопка быстрого запуска задачи с дефолтными параметрами (для каждой модели)
- Форма для создания задачи с кастомными параметрами:
  - Выбор модели
  - Сумма задолженности
  - Сумма пени
  - Дней просрочки
  - Доля оплаченного (0-1)
  - Физическое/юридическое лицо

### 3. Интеграция с ядром

- **БД**: Использует существующие модели из `storage/models.py`:
  - `MLTaskDB` - задачи ML
  - `MLModelDB` - модели ML
  - `UserDB` - пользователи
  - `BillingAccountDB` - биллинговые аккаунты
- **RabbitMQ**: Использует существующий клиент `app/src/rabbitmq_client.py`:
  - Отправка задач в очередь `ml_tasks`
  - Обработка ошибок с возвратом кредитов
- **Архитектура**: Следует принципам SOLID и KISS:
  - Тонкий web-слой: роуты только получают данные и вызывают services
  - Вся бизнес-логика в `services.py`
  - Dependency Injection для сессий БД
  - Переиспользование существующих модулей ядра

### 4. Авторизация

Реализована простая схема авторизации через cookie:
- Cookie `user_id` хранит ID пользователя
- HttpOnly и SameSite=Lax для безопасности
- Dependency `get_current_user_from_cookie` для проверки авторизации
- Пароли хэшируются через bcrypt (как в ядре)
- Автоматический редирект при попытке доступа к защищенным страницам

### 5. Docker и Nginx

#### Docker Compose
Добавлен сервис `web` в `docker-compose.yml`:
- Порт: 8000 (внутренний)
- Зависимости: database, rabbitmq
- Команда: `uvicorn src.webapp.main:app --host 0.0.0.0 --port 8000`
- Переменные окружения для RabbitMQ и БД

#### Nginx (Reverse Proxy)
Настроен сервис `web-proxy`:
- Проксирует запросы с порта 80 на `web:8000`
- Конфигурация в `nginx/nginx.conf`
- WebUI доступен через Nginx на http://localhost:80
- Также доступен напрямую на http://localhost:8000

## Как запустить

### Локально (для разработки)

```bash
# Установить зависимости
cd app
pip install -r requirements.txt

# Запустить приложение
uvicorn src.webapp.main:app --reload --host 0.0.0.0 --port 8000
```

Web-интерфейс будет доступен по адресу: http://localhost:8000

### Через Docker Compose

```bash
# Запустить все сервисы (включая web и web-proxy)
docker-compose up -d

# Проверить статус
docker-compose ps

# Просмотреть логи web-сервиса
docker-compose logs -f web

# Просмотреть логи nginx
docker-compose logs -f web-proxy
```

Web-интерфейс доступен:
- Через Nginx: http://localhost:80 (или http://localhost)
- Напрямую: http://localhost:8000

## Как проверить

### 1. Авторизация

1. Открыть http://localhost:8000 (или http://localhost через Nginx)
2. Перейти на "Регистрация"
3. Создать нового пользователя (email, пароль)
4. После регистрации автоматически войти в систему
5. Проверить, что в навигации отображается email пользователя
6. Выйти через "Выйти" и войти снова через "Войти"

### 2. Главная страница

1. Открыть http://localhost:8000
2. Проверить отображение статистики по задачам
3. Проверить список последних задач
4. Если авторизован - проверить форму создания задачи

### 3. Список задач

1. Перейти на http://localhost:8000/tasks
2. Проверить отображение таблицы всех задач
3. Кликнуть на ID задачи для перехода к деталям

### 4. Детали задачи

1. Перейти на `/tasks/{task_id}` (например, `/tasks/1`)
2. Проверить отображение всех полей задачи
3. Если задача завершена - проверить отображение результата предсказания

### 5. Список моделей

1. Перейти на http://localhost:8000/models
2. Проверить отображение всех моделей
3. Если авторизован - проверить кнопки быстрого запуска
4. Проверить форму создания задачи с параметрами

### 6. Создание задачи

1. Авторизоваться в системе
2. На главной странице или на странице моделей заполнить форму:
   - Выбрать модель
   - Указать параметры (сумма задолженности, пени, дни просрочки, доля оплаченного, тип лица)
3. Отправить форму
4. Проверить редирект на страницу деталей задачи
5. Проверить, что задача появилась в RabbitMQ (через UI http://localhost:15672)
6. Дождаться обработки воркером
7. Обновить страницу деталей задачи - должен отобразиться результат предсказания

### 7. Health check

1. Открыть http://localhost:8000/health
2. Должен вернуться JSON: `{"status": "ok"}`

### 8. Проверка через Nginx

1. Открыть http://localhost (порт 80)
2. Все страницы должны работать так же, как и на порту 8000

## Технические детали

- **FastAPI** с Jinja2Templates для рендеринга HTML
- **SQLAlchemy** для работы с БД через существующие модели
- **RabbitMQ Publisher** для отправки задач в очередь
- **Dependency Injection** для управления сессиями БД
- **Cookie-based авторизация** с HttpOnly и SameSite
- **Минималистичный UI** без внешних зависимостей (чистый HTML/CSS)
- **Nginx** как reverse proxy для production-ready конфигурации

## Эндпоинты

- `GET /` - главная страница (дашборд)

- `POST /models/{model_id}/run` - запуск задачи на модели
